# Second Brain: Memory, Wiki, INGEST

Second Brain is Thansa's "external brain": a directory containing Markdown notes that Thansa reads, accumulates, and remembers long-term. Thanks to it, Thansa not only answers questions during chat but also remembers you, your business, and understands you better over time.

This page guides: what Second Brain contains, how to create and choose multiple different "brains", how to make Thansa remember (long-term memory), and how to "digest" documents (INGEST) to turn raw files into reusable knowledge.

## What is this feature

A Second Brain (also called "brain" or "vault") is a directory on your computer/VPS with sub-folders:

| Layer | Directory | Role |
|---|---|---|
| Sources | `sources/` | Raw notes: articles, screenshots, files you drag in. This is the "original". |
| Wiki | `wiki/` | Distilled knowledge: concepts, frameworks, processes, with cross-links `[[...]]`. |
| Memory | `memory/` | Living memory: what Thansa remembers about you and your business. |
| Agents / Workflows | `agents/`, `workflows/` | Operating layer (see [Agents & Workflows](07-agents-va-workflows.md)). |
| Skills | `skills/` | Skill library, each skill one folder `skills/<slug>/SKILL.md`. Thansa auto-mirrors to `.claude/skills` for Claude Code to load natively (see [Skills](06-skills.md)). |
| Operating layer | `Thansa/` | Generated by chat: recurring loops `Thansa/loops/<slug>.md`, Zalo chat rules `Thansa/zalo/<slug>.md`, reminders `Thansa/reminders.json`, and capability index `Thansa/index.md` (auto-generated, don't edit by hand). |
| Bullet journal | `00 - Dashboard/`, `01 - Daily Log/`, `02 - Weekly Log/`... | Daily notes and tasks; Dataview blocks pull data from here (see [Tasks & Dataview in notes](19-task-va-dataview.md)). |
| Cache zone | `attachments/`, `inbox/` | Images and file attachments; `inbox/telegram/` is where files sent via Telegram land. **These two folders are cache, auto-expire** - read the dedicated section below before storing precious files here. |

The three core layers of "second brain" in the strict sense are **Sources + Wiki + Memory**:

- **Sources** is where raw, unprocessed material lives.
- **Wiki** is distilled knowledge, woven together into a network, exactly what Thansa visualizes in [Knowledge Graph](03-do-thi-tri-thuc.md).
- **Memory** is long-term memory helping Thansa "remember you".

Operating principle: **Sources -> (INGEST) -> Wiki**. Knowledge is accumulated gradually, building up the brain, rather than searching from scratch each time.

## Where brains live on disk

All brains live together in a parent folder called `brains/`, each subfolder is one brain. Running on your machine, it's `brains/` right in the Thansa directory; on Docker/VPS the default is `/brains` (mounted separately for backups). Change location using the environment variable `BRAINS_DIR`, see [Configuration .env](16-cau-hinh-env.md).

The starting brain is named **Brain Default**, located at `brains/Brain Default`.

The `BRAIN_PATH` variable is now legacy from when Thansa had only one brain, kept for data migration. Don't use it to point to the working brain.

## Where to open in Thansa

Second Brain isn't contained in one page but spread across several places on the dashboard (default port `7777`). The navigation rail on the left groups pages, you need to open a group to see sub-items:

1. **Top bar, top left**: brain selector with 3 small buttons ➕ 🗑 📁. This is where you create, select, delete brains.
2. **Chat frame** (**Thansa** or **Conversations** page, **Assistant** group): where you drag files to INGEST and order to "remember this".
3. **Self-learning page** (**Brain** group): memory stats, learn-now button, Curator cleanup, and brain-to-GitHub sync block. See [Self-learning](22-tu-hoc.md).
4. **Files page** (**Brain** group): browse, edit, upload/download all files in brain. See [File management](05-quan-ly-tep-tin.md).
5. **Recurring tasks page** (**Tasks** group): set up recurring tasks so Thansa auto-digests sources on schedule. See [Recurring tasks & Reminders](08-viec-dinh-ky.md).
6. **Settings page** (**System** group): **Interface & Brain** group, **Brain structure** section, to standardize folders.

## Multi-brain: multiple brains in one Thansa

You can keep multiple separate brains - for example, one for business, one for personal learning. Each brain is an independent second brain: sources, wiki, memory, skills, agents all separate.

Brain selector is in the top left corner of the top bar. Next to it are 3 buttons:

| Button | Label (hover to see) | What it does |
|---|---|---|
| ➕ | Create new brain in brains folder | Create a new second brain |
| 🗑 | Delete current brain (confirm by typing exact name) | Move current brain to trash (kept 30 days) |
| 📁 | Select brain from external folder | Point to an existing `.md` note folder on your machine |

The starting brain **Brain Default** cannot be deleted (this is the "root brain").

### Selecting the working brain

1. Click the brain selector in the top left of the top bar.
2. Select the brain you want to use. Each row displays as `🧠 Brain name · 128`, the number after is the count of `.md` notes Thansa found in that brain. If the count hits the limit (5000) there's an additional `+` sign, meaning "at least this many" not the actual total.
3. All Thansa (chat, graph, memory, agents) instantly switch to that brain. No page reload needed.

### Creating a new brain

1. Click the ➕ button next to the brain selector.
2. Type a name in the prompt (line asks "New brain name:"), then confirm.
3. Thansa creates a new subfolder in `brains/` with standard structure (sources, agents, workflows, memory, skills, wiki, attachments and bullet journal pages) and selects the new brain right away.

Brain names have special characters removed (`: * ? " < > |`), leading/trailing dots removed, and are capped at 60 characters for safety.

### Selecting an existing note folder (external folder)

If you already have a `.md` note repository somewhere on your machine (e.g., an Obsidian vault):

1. Click the 📁 button.
2. Select the exact folder containing `.md` files.
3. Thansa uses that folder as a brain. Note: external folders are only "pointed to", the 🗑 button won't delete it from disk (only removes from the list).

The list of external folders is auto-cleaned by Thansa: entries whose path matches an actual brain, or point to a folder deleted from disk, disappear from the menu. If verification fails (server hiccup), the entry is kept to avoid accidental deletion.

### Deleting a brain (to trash, kept 30 days)

Deleting a brain is **not permanent**. Thansa moves the entire folder to local trash then cleans it after 30 days. At the same time, Thansa writes a "death certificate" so the deletion syncs to all machines doing sync, and if you've enabled GitHub backup, the deletion command is pushed to remote immediately rather than waiting for a cycle.

1. Select the brain to delete in the brain selector.
2. Click 🗑.
3. Dialog appears stating: "This brain will be moved to TRASH (kept 30 days then auto-deleted), and deletion will SYNC to other machines." It requires **typing the brain name EXACTLY** to confirm.
4. Type correctly and the brain goes to trash and Thansa returns to Brain Default with message "Deleted brain ... (moved to trash 30 days, synced deletion to other machines)". Type incorrectly and it shows "Name doesn't match - deletion canceled".

Trash is in the `brain-trash` folder in Thansa's state directory (`JAVIS_STATE_DIR`; running on machine it's `server/`, Docker it's the state volume). Each deletion creates a subfolder like `Brain name__20260729-153012`. Cleaning trash older than 30 days runs alongside each brain-to-GitHub sync.

Cannot delete **Brain Default**, clicking 🗑 while it's selected shows "Cannot delete default brain (root brain)."

With external folders (📁), the 🗑 button works differently: it asks 'Remove external folder "..." from list? Only removes from menu, does NOT delete data on disk' then just removes the entry. Disk data stays.

### Standardizing a brain's structure

If a brain has old structure (e.g., notes in `Thansa/agents`, `Memory` capitalized, skill in `.claude/skills`), you can consolidate to unified flat form:

1. Go to **Settings** (**System** group on rail).
2. Open **Interface & Brain** group, scroll to **Brain structure**.
3. Click **Standardize current brain**, then confirm dialog: "Standardize structure of current brain? (Move Thansa/agents→agents, Thansa/workflows→workflows, Memory→memory. Has git backup.)"

This is safe: only moves when destination doesn't exist, no overwrites. It consolidates `Thansa/agents` to `agents/`, `Thansa/workflows` to `workflows/`, `Memory` to `memory/`, and moves old skills from `.claude/skills` to `skills/` (including disabled skill branches, so disabled skills don't get re-enabled).

## `attachments/` and `inbox/` are cache, not storage

This is the rule most likely to lose data if unknown. From version 0.9.247, these two folders are treated by Thansa as **cache**: material passes through, not knowledge.

- Files in these folders older than **30 days** are auto-cleaned. If total size exceeds **300MB**, Thansa cleans from old to new until below the limit.
- Except `.md` notes accidentally in these folders are spared, not cleaned.
- Thansa scans for cleanup every 6 hours. The staging folder (where files you just pasted into chat land) has its own shorter limit: **3 days**.
- These two folders are **outside brain's git**, so they don't go to GitHub backup and don't bloat repo history.
- Expired old images when shown again in chat become a gray box saying **"Image expired"** instead of a broken image icon.
- To turn off auto-cleanup entirely, set `enabled: false` under `media` key in `settings.json`. Day and size thresholds are also adjusted there.

Practical conclusion: documents you want to keep long-term, move to `sources/` or `wiki/`, don't leave them in `attachments/` or `inbox/`. Details in [File management](05-quan-ly-tep-tin.md).

## Long-term memory: making Thansa "remember you"

Living memory is in `memory/` in the selected brain, consisting of:

- `memory/MEMORY.md`: index, one memory per line. This file is loaded at the start of every question, so Thansa always "knows" about you.
- `memory/facts/*.md`: details of each memory, each file is one fact.
- `memory/conversations/YYYY-MM-DD.md`: raw chat log, material for learning.

Thansa classifies 4 types of memory: info about you (`user`), how you like to work (`preference`), business facts (`business`), and settled decisions (`decision`).

### MEMORY.md index has a load ceiling

Because `MEMORY.md` is loaded into **every** chat turn, it has a ceiling around **20,000 characters** (changeable via `JAVIS_MEMORY_INDEX_MAX`). When brain gets dense and exceeds ceiling, Thansa lowers it in steps, prioritizing keeping enough memories:

1. Trim each line description to 100 characters, then 60 characters.
2. Keep only heading and file path, drop description.
3. At most drop some lines, and then Thansa clearly notes how many memories are unlisted plus directions to read further in `Memory/facts/`.

So memories don't vanish, the index just shrinks; full details still live in `memory/facts/` and Thansa reads them anytime.

### Chat logs are masked before saving

Before writing to `memory/conversations/`, Thansa auto-masks secrets you accidentally pasted in chat: API keys (`sk-`, `xai-`, `gsk_`, `hf_`, `tvly-`), GitHub tokens (`ghp_`, `gho_`, `github_pat_`), Google keys (`AIza`), JWT, Telegram bot tokens, `Authorization` headers, and passwords in database connection strings. They're replaced with shortened form like `sk-abc...wxyz` or `***`.

Also each message longer than 4,000 characters gets trimmed middle (keeps 2,800 chars start and 1,000 chars end) with a line noting how much was trimmed, so logs don't balloon.

Two more points worth knowing:

- Chat via **Telegram** is also logged to `memory/conversations/` like web chat, and fed to self-learning loop. See [Telegram channel](11-telegram.md).
- Folder `memory/conversations/` is in brain's `.gitignore`, so raw logs **don't** go to GitHub backup. Git only versions distilled knowledge: `facts/`, `wiki/`, `skills/`, `MEMORY.md`.

### Seeing memory count

Memory count is on the **Index** line on **Self-learning** page (**Brain** group), form `Index · Memories: 87 · Wiki: 42 · MEMORY.md: 18363B ...`. The "Memories" count is the number of files in `memory/facts/` of the selected brain; switching brains changes the number.

The "LONG-TERM MEMORY" widget on the chat column from before has been removed, everything related to learning and memory now goes to the Self-learning page.

### Force Thansa to remember something

While chatting, just say clearly:

- "remember this"
- "note that..."

When you use these phrases, Thansa is forced to create a new memory right away: write a file in `memory/facts/` and add a line to `MEMORY.md`. Example: "Remember this: my shop closes Sundays" gets saved as a `business` fact.

Thansa only records lasting, memorable things. It skips temporary matters and doesn't duplicate existing memories (duplicate then updates the old file).

### Learning from chat (synthesis loop)

This is the loop that gradually makes Thansa smarter: re-read recent chat, extract new facts, merge duplicates, discard wrong memories, and **distill reusable concepts into Wiki**.

This loop now runs auto on server after each chat turn (anti-spam delay), using a read-only isolated learning process; the code that writes files is trusted not AI. On by default.

Key point of this loop: Thansa clearly tells apart two things. Facts about you and business go to `memory/facts/`. But reusable concepts, frameworks, processes go to Wiki as distilled (with `[[wikilink]]`). One thing to one place, so knowledge graph thickens instead of muddling with personal notes.

On/off, choose write mode, choose what to learn, run now, see "what Thansa self-learned" and undo one learning: all on **Self-learning** page. See [Self-learning](22-tu-hoc.md).

## INGEST: digesting documents into knowledge

INGEST is the process turning raw file (article, screenshot, note) into a source in `sources/`, then distilling into Wiki. Result: Thansa summarizes, pulls insights, writes Wiki and can suggest tasks.

### How to use (step by step)

1. Open chat frame (**Thansa** or **Conversations** page).
2. Drag file into chat input box (drag-drop, drop zone says "📎 Drop files here → save to Sources"), or click the paperclip attach button next to input (tooltip "Attach files (images, text, documents) → save to Sources"). Both images and text files work. File uploads to staging.
3. By default, Thansa **only reads and answers**, doesn't save anywhere. If you just need a quick summary, type a normal question.
4. To make Thansa save and digest, explicitly say one of these phrases: **"save to source"**, **"ingest"**, or **"write to second brain"**.
5. Then Thansa will:
   - For text files: read entire, create a clean `.md` in `sources/` with source frontmatter.
   - For images: understand and describe image content in English, create `.md` in `sources/`, move original image to `attachments/` then embed again.
6. From that source, Thansa extracts insights and updates Wiki, while possibly suggesting tasks if the document opens up work.

Remember the cache zone rule above: original images in `attachments/` expire after 30 days, but `.md` files in `sources/` stay forever. That's why you must ingest, not just drag-and-leave.

### Making Thansa process a batch of sources on schedule

If you pile up many unprocessed sources, you can give Thansa a **recurring task** to run in background:

1. Go to **Recurring tasks** (**Tasks** group on rail).
2. Click **+ Add task**.
3. Under **Task type**, keep **🔁 Recurring task**.
4. Set **Name** (e.g., "Digest new sources").
5. Fill **Task description (Thansa does this each round)**, e.g.: "Each round read 1 unprocessed source in sources and suggest a Wiki page to create".
6. Choose **Mode**: **Suggest (read-only)** for Thansa to just propose, or **Auto (safe)** to let it draft files in brain.
7. Set **Cycle (minutes, minimum 5)**, choose **Brain (where to save task)**, then click **💾 Save**.

Details of each mode, how to enable/disable, view logs and safety tips: [Recurring tasks & Reminders](08-viec-dinh-ky.md).

## Checking Wiki (LINT)

When Wiki gets dense, you should periodically audit. LINT only **reads and lists issues**, doesn't auto-fix, so very safe.

The standalone "LINT Wiki" button is gone. LINT now runs inside **Curator** on **Self-learning** page (**Brain** group), with description right on the interface: "Clean index, LINT Wiki (suggestions only), compress MEMORY.md. No deletion."

1. Go to **Self-learning** in **Brain** group on rail.
2. Click **🧹 Curator now** to run once. Button changes to "Cleaning...".
3. Or click the status button in **Curator (periodic maintenance)** section to switch from "○ Off" to "● On", then click **💾 Save settings** for Thansa to auto-run on schedule (Curator default off, cycle when on is 24 hours).

Results don't fix anything, just dump into the **Learning log** below as "Wiki LINT (suggestions, not fixed)". It finds: duplicate pages, orphan pages (no one points to them), broken `[[...]]` links, unresolved contradictions, and thin knowledge gaps. Read the list then decide what to fix yourself, don't let Thansa mass-edit.

## Tips

- **Split brains by purpose.** One brain for business, one for personal keeps knowledge graph and memory clean, less noise.
- **Say "remember this" for lasting things.** Example: market niche, main sales channel, settled pricing. Don't record passing matters (today busy, message just sent), Thansa already skips those.
- **Must say it clearly to ingest documents.** Dragging alone isn't enough to save, must say "save to source" or "ingest". Just normal question means Thansa reads then stops.
- **Memory follows the folder.** Switch machines or move VPS, just point Thansa to the right brain folder and all memories and Wiki stay.
- **Don't hand-build git for sync yourself.** Thansa already has **⇅ Sync brain with GitHub (2-way)** block on Self-learning page: push entire brains folder to a private repo and pull changes from other machines. Step-by-step guide in [Backup brain to GitHub](18-sao-luu-github.md).
- **See knowledge visually** in [Knowledge Graph](03-do-thi-tri-thuc.md): each source and Wiki page is a point, `[[...]]` links are lines.

## Common issues

- **Can't find "LONG-TERM MEMORY" widget or "Learn from chat now" button in chat column.** Widget removed. Everything about learning and memory is now on **Self-learning** page (**Brain** group): memory count in **Index** line, learn by hand with **▶ Learn now** button.
- **Memory count still 0 even after lots of chat.** Memories only recorded when lasting, memorable info exists, or you say "remember this", or after running learning. Casual chat doesn't create memories. Check Self-learning page to see if self-learning is on and write mode is **Auto-write**.
- **Dragged file but doesn't appear in Sources.** By design: default is read-only. Must type "save to source" / "ingest" in message so Thansa creates `.md` in `sources/`.
- **Old image in chat became gray box "Image expired".** By design: `attachments/` is cache, images over 30 days cleaned. Image content was extracted to `.md` in `sources/` during ingest so it remains.
- **Deleted brain by accident.** Not lost immediately: folder is in `brain-trash` in Thansa's state folder, named like `Brain name__20260729-153012`, kept 30 days. Safe recovery: click ➕ to create new brain with **exact old name** (action removes death certificate so brain won't be deleted again on sync), then copy content from trash to that folder.
- **Brain says structure not standardized.** Go Settings, Interface & Brain group, Brain structure section, click **Standardize current brain** to have Thansa consolidate folders.
- **Memories don't transfer to new machine.** Check you pointed to the right brain folder with `memory/`. Memory is in folder, not account. To auto-sync two machines, turn on GitHub sync, see [Backup brain to GitHub](18-sao-luu-github.md).
- **GitHub backup done but no chat logs or images.** By design: `memory/conversations/`, `attachments/` and `inbox/` all outside brain's git. Backup only keeps distilled knowledge.
